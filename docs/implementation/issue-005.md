# Issue 005 — 单时钟实时对局集成（盖伦诊断演练）

日期：2026-10-31。状态：**PARTIAL**。GitHub 代码已提交；真实 Chromium 游戏联调和 Sites 发布尚未完成。

## 本阶段实际内容

- 新增 `dist/rebuild/live-session.js`：将 `match.js` 的准备／追捕／计分、`encounter.js` 的真实导航移动与近战抓捕、`vision-baseline.js` 的角色独立可见性统一到单一实时模拟时钟。每帧限制模拟增量，内部按最大 50ms 子步推进；AI 定期更新路线，AI 追捕者可按可见性与距离条件进行抓捕，玩家角色也可被淘汰。
- `app.js` 接入盖伦的现有移动、朝向及 A 攻击输入；准备阶段玩家追捕者不得离开当前起点，抓捕将调用合法性判定、淘汰和结算。视野内的 AI 对手以明确的虚线“诊断目标”圆圈标识，隐藏目标不显示；这**不是**其他英雄模型，也不表示已达到正式画面要求。
- `round-lab.js` 新增“启动实时演练（盖伦）”和停止按钮及实时状态区。使用真实经过时间，而非人工点击增加 30 秒。单局支持选择 2–4 人和盖伦为玩家操控英雄、玩家追捕者或躲藏者；其他英雄仍只有逻辑对象，暂无正式模型和动画。旧规则预演和导航诊断保持独立。
- 玩家抓捕增加基于模拟经过时间的短冷却；AI 仍受原始导航与当前独立视野基线约束；全局结果由同一 match 状态产生。

## 实际执行验证

从 GitHub 回读本阶段 JS 源文件，在 JavaScript 执行环境加载并调用原有测试与新增 `tests/live-session.test.mjs` 六项：**28/28 PASS**。另通过脚本语法解析检查新增模块与入口模块。未在完整仓库本地运行 Node.js `node --test`，也未进行真实游戏画面性能或端到端浏览器测量。不得以这些单元测试代替实际视觉验收。

## 重要剩余问题

- 只有盖伦有原始匹配渲染素材。其他英雄在实时演练中仅存在逻辑坐标，诊断圈不能作为正式英雄占位美术交付；玩家角色只能选择盖伦。
- 战斗当前使用即时攻击判定，尚未绑定原模型攻击动画的具体命中帧和攻击冷却完整规格。敌方 AI 只有有限追逃逻辑，没有正式复杂策略。
- 追捕者的准备阶段暂锁定于当前探索起点，**并非地图真正泉水区域**；正式泉水起点和释放路线尚未实现。
- `vision-baseline.js` 依靠 walkable 与 bush ID 的保守近似，尚无游戏本体专用 vision blocker、完整战争迷雾覆盖或正式小地图过滤；开发调试面板内部能看到诊断数据。
- 当前脚本运行通过游戏 RAF，后台标签页可能限速；没有完整浏览器端时钟连续性与可见性验收，也没有技能、野怪实体或八条海克斯。
- GitHub 与 Sites 是分开的部署系统；本回合仅提交 GitHub，不宣称体验站点已同步。Issue 001–005 均仍为 PARTIAL。
