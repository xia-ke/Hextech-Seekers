# Issue 003 — 原始导航约束的 AI 移动和近战抓捕判定

日期：2026-10-31。状态：**PARTIAL（逻辑和导航诊断已实现，不是可玩的真实追捕对局）**。

## 已实现
- `dist/rebuild/encounter.js`：在实际导航接口下创建实体逻辑位置，沿 A* 路径按速度逐帧移动，碰到不可通行区域停止。
- 准备阶段限制追捕者移动；追捕阶段才允许记录合法抓获；检查阵营、距离、朝向、目标可见性及阻挡；成功后设置淘汰并调用现有 `match.js` 的单局结算。
- `chooseAiDestination` 不读取全局隐身敌人信息。未提供视野函数时不追逐任何目标，只能按外部提供的巡逻点移动；躲藏 AI 在确实看到敌人时可以选择远离方向。
- `app.js` 地图完成加载时暴露 `window.__hextechNavigation` 的寻路/通行适配层。`round-lab.js` 新增“实际导航 AI 移动演练”控件，演练角色使用原地图导航计算和显示逻辑坐标，**不生成或渲染替代英雄模型**。
- `tests/encounter.test.mjs` 7 项覆盖准备阶段、合法位置、路线移动、视野与朝向、攻击判定、非全知 AI、躲藏移动行为。

从 GitHub 读取六个源码/测试文件，通过 JS 引擎加载执行 7 项原有规则测试及 7 项新增机制测试：**14/14 PASS**；新网页模块及现有 app.js 去除 import 后可解析。测试并非在完整克隆工作目录内执行 `node --test`，没有声称通过真实浏览器视觉验收。

## 限制与下一步
- 抓捕合法性已建模，但角色实际近战输入、攻击动画命中事件、AI 自动攻击仍未接入。玩家探索中的“攻击动作预览”仍不触发捕获。
- 没有正式 LoL 视野/草丛/墙体视野判定；`visible` 必须由未来统一视野模块注入。单独的 `nav.lineClear` 只是可行走路径检查，不能替代视野射线或所有地形命中规则。
- 其他英雄的正版模型/动作仍未进入网页。当前导航演练只显示坐标，不将 UI 坐标标签描述为真实英雄实体渲染。
