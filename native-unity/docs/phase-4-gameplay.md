# Native Unity Phase 4 — first playable hide-and-seek vertical slice

Status: SOURCE IMPLEMENTED; authoritative Editor rules tests and a native Windows Player gameplay smoke are connected to CI. **Do not call Phase 4 accepted until the new Unity Editor and GPU gameplay runs pass.** This is not yet the full V1.

## Launch and controls

Open the pinned original 3D Rift in the native Windows Player or Unity Editor Play Mode. The scene is generated by `HextechNativeSetup.CreateScene()`; the build action `HextechNativeSetup.BuildWindows()` regenerates that scene and bundles URP and original champion resource data. After the 3D Rift and Garen finish loading, choose **Play as HUNTER** or **Play as HIDER** in the top-left menu. The current opponent is a distinctly labeled tactical **AI position ring**, not a second original League champion. One human Garen and one training opponent constitute the first playable test round.

- **Right mouse button** — click ground to navigate along the original `RiftGrid` walkable A* route.
- **S** — stop moving.
- **A** — hunter's basic attack animation and capture check during pursuit; not a hero skill and not a hit on animation event yet. Hunters cannot capture during setup.
- **Return to role select** — appears after the round ends, without Unity scene reload.
- The camera follows the original skinned Garen. Existing `-hextechVisualQA` is untouched by the new gameplay UI/AI.
- AI travel uses the same native grid and constrained paths, with decisions refreshed ~0.65s apart. AI only follows a target when it can see that target through its *own* LOS/bush test; otherwise it explores. The 3D tactical ring is hidden when not in the human player's LOS.

## Rule implementation

`NativeMatchRules.cs` is deliberately presentation-independent: supports **one hunter plus 1–3 hiders**, unique participant IDs/hero slots, one human player, 2–4 entrants, and round lifecycle `Lobby → Preparation → Pursuit → Finished`.

Confirmed rules taken from `docs/implementation/v1-rules.md` and `Hextech-Seekers_state_20261030.md`:

| Item | Implementation |
| --- | --- |
| Setup phase | Fixed **120s**. Hunter cannot move or attack; hiders can navigate. |
| Chase duration | **3 + 2 × (X − 1)** minutes for X hiders (X=1,2,3 → 3,5,7 minutes). |
| Capture | **One valid basic attack** by the hunter during pursuit, with target in tactical LOS and within provisional 130-world-unit reach. No ordinary skill directly captures. |
| Caught hiders | Eliminated from current round. Repeated attacks cannot capture/score again. A human hider remains in the scene to spectate. |
| Chase ends | After all hiders captured or pursuit clock expires. |
| Hunter score | **X − S**, plus 1 if all hiders captured by **3 + 2 × (X − 2)** minutes of pursuit, with S surviving. |
| Hider score | S=0 → all 0. S=1 → sole survivor ceil(X/2), each captured hider 1. S≥2 → surviving hiders S each, captured hiders 0. |
| AI vision | Individual `NativeSight` visibility using original navigation clearance + bush IDs; no omniscient target tracking. |
| Hunter movement | Provisional ~7.4% bonus (365 vs 340 nav-world units/sec). Needs gameplay tuning. |

### What is implemented / not implemented

This slice genuinely connects **role selection, native navigation, state clock, AI search/chase/flee, attack-to-capture gating, spectator state, scores and a replay entry** to the original Rift/real Garen. It does **not** claim to be the complete game:

- **Other original heroes:** Blitzcrank, Riven and Yasuo rig/models are still needed. The tactical training marker is not a fake playable champion. Champion selection and the 2–4-member UI remain later work; the rules engine already validates this capacity.
- **Riot-accurate fog of war:** Current individual sight checks only the navigation grid's obstacle clearance, distance and bush IDs; there is **no full darkened map/shader fog or engine-accurate vision polygon** yet.
- **Fountain:** Hunter is immobilized at a *provisional staging point* for 120 seconds; authentic fountain coordinate/movement boundary remains to be calibrated using the original scene. Do not describe the staging point as a confirmed fountain implementation.
- **Hit validation:** Attack reach+visibility is an alpha tactical hit gate, not yet an actual weapon animation contact volume/event.
- **Champion skill white-list, wild monsters, independent three-choice eight-augment system, protection/immunity and final 2–4-character roster** have not been added.
- Currently single 1v1 human-vs-AI session. The generic engine can score up to 4 participants, but AI representation/controller currently supports one tactical opponent only.

## Test boundaries

- `NativeMatchRulesTests.cs`: 11 EditMode tests for correct timers, carry-over, scoring cases, basic-attack-only capture, no duplicate hero IDs and bush vision.
- `.github/workflows/unity-windows-selfhosted.yml`: Unity C# compile + **all** EditMode tests.
- `.github/workflows/unity-windows-visual.yml`: original 3 PNG screenshots from existing `-hextechVisualQA` followed by the **new** real Windows Player `-hextechGameplayQA` runtime integration smoke:
  1. Load original 3D Rift/real Garen.
  2. Start hunter role, verify hunter is locked for preparation.
  3. Advance exactly 120s game *clock* (without taking 120s wall time), release hunter, use basic-attack capture logic on the same navigable tile and verify early-capture scoring/elimination.
  4. Reset, start hider role, verify hider can move and AI hunter cannot during preparation; advance a full 3-minute pursuit game clock; verify survival and scoring.
  5. Write `gameplay-result.json` with PASS or failure reason and exit Player with corresponding status.

The smoke directly uses live scene, controller, navigation and model, but is **not** an automated end-to-end human mouse/keyboard usability test or a 3D hero-versus-hero visual comparison. A green CI result proves the integration smoke; real gameplay and screenshots still need visual and interaction review.

Evidence remains local on the Windows self-hosted Runner under `F:\actions-runner\HextechVisualEvidence\<run-id>\`; this prevents the codeload-dependent artifact action from blocking CI. The real Player EXE is not uploaded or licensed for public distribution.
